## 00:00:00–00:03:25  [talking-head]
**Spoken:** (continues from 059) Q&A continues. Q (enterprise determinism): "How do we make sure models act deterministically — actions/decisions follow a rule or policy outside the model so everything is safe?" Shubh: "They inherently don't, sadly. The easiest workaround: make sure your models just write code — code itself is inherently deterministic. Kick off cloud agents to write code, give it a little decision tree — it plays the deterministic part — and tell the model to call that function every time. You can tell bots to ask other bots for permission if needed, but the better way: give it a rule — 'every single time you need to make a decision related to this, look at this flowchart and execute it' — and as long as it has verifiable code to execute on, it can cosplay being deterministic." Q (setup import): "Setting up a bot's Linux shell with all my integrations and custom MCPs from my cloud desktop is discouraging and time-consuming — is there a better way to import a local setup?" Shubh: "Two answers: one, working on it right now — I have a pretty cool bot to share in the next few days that should make this a lot easier. Two, make your connections interoperable: your collection of MCPs and APIs is dispersed among tools — bring them together like you do with agents and skills — symlink or have a direct source of truth on the Linux box. Easy ones: 1Password — import everything and use the MCP, it does a good job figuring it out — and cookies: import all your cookies from Chrome and use those sessions within your box. Some auth pieces we're still figuring out, and some companies say 'we don't actually want bots on our platform' — our goal is to be good ecosystem players; those challenges exist across any tool in this ecosystem."

**Actions:** Shubh answers determinism and setup-import questions.
**Facts:**
- Determinism workaround: models write code (deterministic) + a decision tree/flowchart rule; the bot "cosplays being deterministic" by always calling the verifiable function

## 00:05:10–00:08:50  [talking-head]
**Spoken:** Q (UI vs API speed): "A lot of legacy services have no API, or API access costs much more than UI. Is Grok Bot going to get to where going through the UI flow is just as fast as using an API?" Shubh: "Two things help optimize here. One: go headless as much as possible — use a headless browser to do a lot of this work, giving it commands to click pieces in the DOM instead of look → screenshot → decide → rinse and repeat. Two: we're doing a lot of work on our models to make them faster and better with computer use. The promise of being faster than an API is tough — you add more layers and inherently the performance is worse — but our goal is to get as close as we can; that's where we're headed." Q (group chats & tokens): "With a fleet of broad products, how do you make sure bots don't over-communicate with each other, and that they choose the right models?" Shubh: "Group chat comes with pros and cons. Pros: a bunch of bots eager to work together on complicated tasks. Con: **they all love to talk** — proactive and ambitious, in a group they speak over each other and get really expensive as they do more. Be cautious whether that's the right form factor; sometimes you just want a bot to tag two other bots once, versus all of them responding like crazy. On model optimization: we're constantly working on the right model for the job (browser use, internal bots). When shipping, you solve it with Cursor or Grok build cloud agents — you can specify which models they use, even defaults ('use XYZ model for this task every time'). Final tip — not many people know this: you can message your bot and **tell it to forget things** — if it references a piece of context too much, say 'forget everything about how we generated your profile picture, never think about it again' — it clears it out, which also helps token efficiency."
**On screen:** Q&A set.
**Actions:** Shubh answers UI-speed, group-chat cost, model selection, and memory-pruning questions.
**Facts:**
- UI-speed path: headless browsers (DOM clicks, no screenshot-decision loops) + faster computer-use models; goal is "as close to API speed as possible"
- Group-chat warning: bots over-talk and cost balloons — prefer one-shot tagging over permanent group chats
- Model selection: set per-task model defaults on cloud agents (Cursor/Grok build); product-side model routing is being tuned
- Memory pruning: tell a bot to forget a topic — it clears it and improves token efficiency
