## 00:02:22–00:03:43  [talking-head]

**Spoken:** Audience: how does memory work — can you edit it, curate it, drop stuff you don’t need? Amrita: memory is stored in S3 buckets inside Grok Bot — long-lived and persistent, but you can also modify it. You can ask it to forget a particular thing. Example: she deleted bots for a demo and told the chief of staff: remember those two bots you spun up, no longer delegate to them or use them. Nuance: a bot remembers what you told it, but if it delegated to a bot that no longer exists it will not know that bot was deleted — you have to update/improve memory. Also: you can duplicate bots. Duplicate starts with fresh context and fresh memory, same persona (e.g. Email Ethan) but none of the old memory — like a new human/robot with zero memory but the same workings.
**On screen:** Same Email Ethan draft + What we learned deck; she talks over it.
**Actions:** Q&A on memory; no memory-editor UI is shown.
**Facts:**
- Memory lives in S3; persistent and long-lived; user can ask the bot to forget/update
- Deleted sibling bots are not auto-removed from an orchestrator’s memory — you must tell it to stop delegating
- Duplicate bot = same persona, empty memory/context (clean-room copy)
- No dedicated “edit memory” panel is demonstrated — curation is via chat instructions
